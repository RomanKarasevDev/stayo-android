# Резервные копии проекта Stayo

Войдите через `/login`, откройте проект и вкладку **Резервные копии**.
`/admin` — отдельная панель оператора сервера. Её bootstrap token не нужен
для работы в клиентском кабинете.

## Создать копию

1. Введите текущий пароль от кабинета и нажмите **Создать копию**.
2. Дождитесь завершения операции. Принятый запрос ещё не означает готовую копию.
3. Проверьте, что копия доступна для восстановления.

Для создания нужен запущенный проект и настроенное оператором зашифрованное
хранилище резервных копий. Пока выполняется другая операция проекта, кнопка
недоступна. В кабинете показаны последние 100 копий и их метаданные. Значения
секретов, ключи восстановления и доступ к хранилищу здесь не отображаются.

## Восстановить проект

1. Выберите копию нужной даты. Сохраните отдельно изменения, которые появились
   после этой даты и должны остаться: восстановление заменяет текущее состояние.
2. Введите точное короткое имя проекта и текущий пароль от кабинета.
3. Подтвердите восстановление и дождитесь статуса завершения. Во время операции
   API проекта временно недоступен.
4. Проверьте данные и файлы, затем разделы **Секреты** и **Функции**.
5. Вызовите опубликованную функцию из приложения.

Восстанавливаются данные, файлы, именованные секреты, черновики и отдельно
сохранённые опубликованные версии функций. Черновик остаётся черновиком:
восстановление не публикует его автоматически. Секреты снова шифруются с
привязкой к проекту и имени. Для выполнения функции они передаются через
закрытое временное хранилище в памяти сервера.

Если запрос оборвался, проверьте состояние операции. Браузер не повторяет
изменения автоматически. Повтор того же запроса в открытой форме с тем же
ключом идемпотентности возвращает прежнюю задачу; после перезагрузки страницы
может быть создана новая задача. При ошибке восстановления обратитесь к оператору:
публичный API может оставаться в режиме обслуживания до исправления причины.
Новые копии заблокированы до успешного завершения повторного восстановления.
Работающие контейнеры и изменение других настроек этот запрет не снимают.
Восстановление из существующей копии остаётся доступным.

Это восстановление на действующем сервере. Восстановление после потери сервера
и основного ключа выполняется отдельно с ключом аварийного восстановления.

[Контракт API и английская инструкция](cabinet-backups.md) ·
[Секреты и функции](secrets-and-functions.md)

После восстановления заново подключите подписки Realtime и запросите актуальные
данные приложения. Realtime продолжает штатную очистку просроченных служебных
сообщений; сохранённые события не гарантируют повторную доставку подписчикам.

Повторный сценарий на сборке `2ae0d7e` — секреты, функции, зашифрованная копия,
восстановление и настоящая перезагрузка тестового VPS — описан в
[отчёте от 23 октября](release-status.md#verification).
Создание копии и изменения выполнены в Safari; восстановление и финальные
проверки — в отдельном фоновом Chromium.

Исторический полный сценарий кабинета на сборке `0903969` — секреты, функции,
копия и восстановление в Safari/Firefox, а также подробная проверка перезагрузки —
описан в [отчёте той сборки](release-status.md#verification).
[Исторический отчёт `e1d8474`](release-status.md#verification) сохраняет
результаты той сборки и проверки аварийного прерывания.
Историческая проверка старых партиций Realtime, файлов и Safari на предыдущих
сборках приведена в [отчёте `1365e19`](release-status.md#verification).
[Отдельный тест](release-status.md#verification) проверяет повреждение
данных и очистку старых сообщений.

При перезапуске сервера во время восстановления доступные задания продолжаются.
После проверки данных сервер сохраняет переход к открытию доступа. С этого
момента повторный запуск завершает только этот переход и не загружает копию
заново: новые записи приложения сохраняются. Отмена после успешной проверки
также даёт серверу завершить открытие доступа.

Старое прерванное задание, созданное предыдущей версией, может потребовать помощи
оператора. Оно не запускает импорт автоматически. Перед повторным восстановлением
сохраните нужные текущие данные. Проверки аварийного прерывания и точная версия
сборки приведены в [отдельном отчёте](release-status.md#verification).
